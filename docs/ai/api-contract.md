# AI API Contract

## 1. Endpoint Contract

Every AI backend adapter must implement:

```ts
generateChunks(input: GenerateChunksRequest): Promise<GenerateChunksResponse>
```

The transport may be HTTP, Apps Script, Supabase Edge Function, or a native
gateway. The adapter translates transport details into this contract.

## 2. Request

```ts
interface GenerateChunksRequest {
  requestId: string;
  contractVersion: "1";
  promptVersion: string;
  diaryContent: string;
  nativeLanguage: string;
  targetLanguage: string;
  cefrLevel?: string;
  learningPurpose?: "hobby" | "work";
  specialty?: string;
  subSpecialty?: string;
  profileContext?: string;
  existingSemanticGroups: SemanticGroupInput[];
}

interface SemanticGroupInput {
  id: string;
  canonicalMeaning: string;
  coverageLevel: number;
}
```

Rules:

- `requestId` is generated by the client and is used for diagnostics and
  idempotency. It is not an authorization credential.
- `diaryContent` must be non-empty and have a server-enforced maximum size.
- `existingSemanticGroups` must be capped, for example at 80 records.
- The client may send a user id for telemetry, but the gateway derives ownership
  from the authenticated session.
- The gateway must not trust model, provider, quota, or user ownership fields
  supplied by the client.

## 3. Response

```ts
interface GenerateChunksResponse {
  requestId: string;
  contractVersion: "1";
  promptVersion: string;
  englishNarrative: string;
  semanticUnits: SemanticUnit[];
  usage?: {
    inputTokens?: number;
    outputTokens?: number;
    model?: string;
  };
}

interface SemanticUnit {
  order: number;
  nativeText: string;
  englishText: string;
  commonChunks: ChunkCandidate[];
  personalizedChunks: ChunkCandidate[];
}

interface ChunkCandidate {
  english: string;
  text: string;
  meaning: string;
  ipa: string;
  romanization: string;
  semanticGroupId: string;
  proposedCanonicalMeaning?: string;
}
```

The transport envelope should be stable:

```json
{
  "success": true,
  "result": { "requestId": "...", "contractVersion": "1", "...": "..." },
  "error": null
}
```

`result` should be an object, not JSON encoded as a string. During migration,
the adapter may temporarily parse the legacy string response, but new endpoints
must return the object form.

## 4. Error Contract

```ts
type AIErrorCode =
  | "INVALID_REQUEST"
  | "AUTH_REQUIRED"
  | "PROFILE_REQUIRED"
  | "RATE_LIMITED"
  | "PAYLOAD_TOO_LARGE"
  | "PROVIDER_UNAVAILABLE"
  | "PROVIDER_TIMEOUT"
  | "INVALID_MODEL_OUTPUT"
  | "CONFIGURATION_ERROR"
  | "INTERNAL_ERROR";

interface AIErrorResponse {
  success: false;
  requestId?: string;
  error: {
    code: AIErrorCode;
    message: string;
    retryable: boolean;
  };
}
```

User-facing messages are mapped in the client. Provider error text, API keys,
stack traces, and raw prompts must not be returned to the user.

## 5. Validation Rules

Validate both at the gateway and in the client before persistence:

- Required top-level strings are present.
- `order` is a positive integer and unique within a response.
- Every chunk has non-empty `text`, `meaning`, and `english`.
- `chunkType` is assigned by the containing array, not by the model.
- `semanticGroupId` is either an existing supplied id or an empty string.
- New groups require `proposedCanonicalMeaning`.
- Chunk counts and total output size remain within configured limits.
- Unknown fields are ignored after parsing; malformed required fields reject the
  complete response rather than partially writing data.

## 6. Compatibility Matrix

| Backend | Status | Required behavior |
|---|---|---|
| Google Apps Script | Current beta | Adapt legacy request/response to canonical contract |
| Supabase Edge Function | Migration target | Native canonical envelope, server-side auth and model config |
| Express local server | Development only | Must not silently diverge from canonical contract |
| Native mobile gateway | Future | Reuse canonical contract, no provider logic in the app |

## 7. Versioning

Breaking changes require a new `contractVersion`. Prompt-only changes increment
`promptVersion`. The client should reject unsupported contract versions with a
clear configuration error.
